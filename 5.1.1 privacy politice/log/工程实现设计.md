#  实验流程的工程化端到端实现方案

 在对大模型进行微调时引入了很多噪声，大模型一直在输出0 (Other)。而且大模型无法像BERT一样采用LW加权损失学习(为什么？)我们决定重新分析这个任务，我们观察到BERT+LW方法分类性能很好，而LLMs强在推理而不是直接输出分类，为了决定扬长避短，发挥两者优势，我们想提出两阶段任务：

1. 训练一个分类器(`deberta-v3-base`)，只输出0和1(如果输入句子属于Other分类输出0，否则分类输出1)，如果输出0则任务直接结束。
2. 如果输出1则把句子喂给LLMs进行推理输出(1-10)。

## 第一步：实现实现两个模块(XXXX.py)

#### 模块一：微调的`deberta-v3-base`

1. 加载预训练编码器：进行模型的高效实例化：使用 `AutoModelForSequenceClassification.from_pretrained("microsoft/deberta-v3-base", num_labels=2)` 直接加载具备解耦注意力机制的预训练权重。 

2. 损失函数定制：随后，**定制核心 Trainer 类**：通过继承原生的 `Trainer` 基类，重写关键的 `compute_loss` 方法 在具体的底层数学实现中，首先提取数据字典中的 `inputs.get("labels")`，接着调用PyTorch底层的 `F.cross_entropy(logits, labels, weight=class_weights, reduction='none')` 函数计算带有权重的未缩减基础损失。在此基础上，将有效样本数平滑权重(ENoS) + Focal Loss 结合定义权重 ”。 在训练超参数的设定上，由于`DeBERTa-v3`的相对位置编码机制异常敏感，初始学习率绝不宜过大（一般建议控制在 $2e-5$ 至 $5e-5$ 的狭窄区间内），并必须配合具有一定Warmup步数的线性衰减学习率调度器。同时，强烈建议启用Early Stopping机制，且其监控指标必须锁定在验证集的 **Macro-F1** 分数应对极度不平衡数据。

3. 参数调优：找到一个精心调优的预测概率阈值分割点（通过在验证集上优化F-beta分数，而不仅仅是死守0.5），将低于阈值的样本无情拦截，并直接为这些样本打上最终的“0 (Other)”标签，且不计入后续计算成本。要求该阈值尽可能多提升标签1-10的召回率的同时精确率也最高

4. 数据集为./datasets/data.tsv

   ```tsx
   0	Frans Erenstraat 14A 	www.idates.com
   0	Support requests via compliance @ as well as email attachments will not be opened/considered due to security regulations . 	www.idates.com
   ```

## 第二步：使用Haystack连接这两个模块构建完整的可进行推理评估的系统(LLM_reasoning.py)

实现以下闭环逻辑：

1. 将全量测试集样本不经任何预处理地输入第一阶段已经训练完毕的DeBERTa-v3分类器。 
2. 将顺利通过过滤器的“高嫌疑”隐私句子样本提取出来，依据索引自动去源文档中调取相应的Context和Summary，动态拼接并构建成完整的评估Prompt。
3. 利用vLLM等极致优化的推理加速框架部署微调后的Llama 3.1-8B模型，对这些庞大的Prompt队列进行高并发的批量推理（Batch Inference），大幅缩减学术实验的迭代等待时间。
4. 从大模型生成的夹杂着人类自然语言的推理文本中，精准提取出最终的标准化标签（1-10）。 最后，进行统一的性能评估计算。汇总第一步直接拦截的零类结果与第五步提取的非零类结果，并与未经任何篡改的原始金标准（Ground Truth）标签对齐。使用 `sklearn.metrics.classification_report` 生成一份涵盖所有类别（0至10）的宏观（Macro）与微观（Micro）Precision、Recall、F1-Score综合性能报告。
